# AssetDataBase

办公类固定资产明细数据库，用于通过 ChatGPT / Codex 持续维护公司的办公资产台账、盘点状态和变更流水。

## 当前口径

资产主档以《2026年办公类固定资产年度盘点册（0724）》上传表格为准，`data/assets.csv` 完全沿用原明细表字段和字段顺序：

| 字段 |
|---|
| 序号 |
| 资产编号 |
| 资产名称 |
| 规格型号 |
| 资产类别 |
| 权属单位 |
| 现使用单位 |
| 购置日期 |
| 账面原值 |
| 账面净值 |
| 使用部门 |
| 存放地点 |
| 使用人 |
| 资产现状 |
| 原固定资产编码 |
| 盘点情况 |

## 目录结构

| 路径 | 说明 |
|---|---|
| `data/assets.csv` | 资产主档，严格按照原盘点册 16 列维护 |
| `data/asset_events.csv` | 资产事件流水，记录补录、调拨、维修、盘点、报废等动作 |
| `templates/asset_intake_template.csv` | 新增或批量补录资产模板，表头与主档一致 |
| `docs/field_dictionary.md` | 字段字典与填写规则 |
| `docs/asset_workflow.md` | 资产购置、调拨、维修、报废流程 |
| `docs/chat_update_protocol.md` | 通过聊天维护资产数据库的操作约定 |
| `scripts/sync.sh` | 本地仓库同步脚本 |

## 推荐维护方式

1. 新增资产：在 `data/assets.csv` 按原表 16 列新增一行，并在 `data/asset_events.csv` 追加一条 `purchase` 或 `register` 事件。
2. 调拨资产：更新 `使用部门`、`存放地点`、`使用人`，必要时更新 `现使用单位`，并追加 `transfer` 事件。
3. 维修资产：根据实际情况更新 `资产现状` 或 `盘点情况`，并追加 `repair_start` / `repair_done` 事件。
4. 报废资产：将 `资产现状` 更新为 `待报废` 或最终确认状态，并追加 `dispose` 事件。
5. 每次修改后提交到 GitHub，保持所有设备同步。

## 状态口径

当前盘点册中的 `资产现状` 包含：

| 状态 | 含义 |
|---|---|
| 在用 | 当前仍在使用或由部门统一管理 |
| 闲置 | 当前未分配到具体使用场景，可后续调拨 |
| 待报废 | 已进入或准备进入报废流程 |

后续如果出现维修中、已报废、遗失等状态，应先确认是否加入台账枚举，再统一维护。
